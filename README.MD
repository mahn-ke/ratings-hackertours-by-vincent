# ratings.hackertours.by.vincent.mahn.ke

Hosts the container serving [ratings.hackertours.by.vincent.mahn.ke](https://ratings.hackertours.by.vincent.mahn.ke).

The tour ratings of the Hackertours consoles (Nintendo 3DS, Xbox 360, Nintendo Switch, and the Game Boy Advance through its
link server): after a tour a guest rates its content and its guide (1–5 stars), says whether it was too short or too long, and
may leave a drawing. The ratings are for the team: there is **no public read API**. A rating carries no personal data, and no
address is logged.

Node.js 26, built-in SQLite (WAL) and a directory of PNG files. Keycloak client-credentials authentication with the consoles'
service accounts of the shared high scores (and the GBA link server's); the platform of a rating is the token's `azp`. The
machine-readable API is at `/openapi.json`.

## API

| Method | Path | Authentication | Result |
| --- | --- | --- | --- |
| GET | `/healthz` | None | `{"status":"ok"}` after a database read |
| GET | `/openapi.json` | None | the OpenAPI 3.0 description |
| POST | `/api/ratings` | Bearer access token | 201 for a new rating, 200 for a known id |
| PUT | `/api/ratings/{id}/drawing` | Bearer access token | 201 for a new drawing, 200 for the same or a replaced one |

### POST /api/ratings

`Content-Type: application/json`, at most 4096 bytes, with **exactly** these fields (an unknown or missing one is a 400):

```json
{"id":"r-1792956000.abc","time":1792956000,"session":"a1b2c3d4","organizer":"hackertours","event":"40c3","item_id":17,
 "tour":"Hackertour (Deutsch)","lang":"de","content":5,"guide":4,"duration":"perfect",
 "game_title_id":"4D5307E6","game_name":"Halo 3","game_type":"disc","build":"1.4.0"}
```

| Field | Validation |
| --- | --- |
| id | `^[A-Za-z0-9._-]{1,64}$`, generated by the console; the idempotency key, unique per platform |
| time | integer Unix **seconds** ≥ 0 (the console's clock) |
| session | string of at most 64 characters, or `null` |
| organizer, event | the shop's slugs, strings of at most 64 characters |
| item_id | integer ≥ 0, the shop item of the tour |
| tour | string of at most 200 characters |
| lang | `en` or `de` |
| content, guide | integer 1–5, or `null` when skipped |
| duration | `way_too_short`, `too_short`, `perfect`, `too_long`, `way_too_long`, or `null` |
| game_title_id | string of at most 32 characters, or `null` |
| game_name | string of at most 200 characters, or `null` |
| game_type | `disc`, `arcade`, `gba`, or `null` |
| build | the console app's build, string of at most 64 characters |

Lengths count characters (code points), not bytes. Both 200 and 201 return the stored row: the fields above plus `platform`
(`3ds`, `xbox`, `switch` or `gba`, from the token's `azp`; never send it). Keep the same id across retries: a known
(platform, id) returns the stored row unchanged, even when the new fields differ.

### PUT /api/ratings/{id}/drawing

`Content-Type: image/png`, at most 65536 bytes, starting with the PNG signature, sent **after** the rating was stored (404
otherwise, also for another platform's id). The drawing is stored as `{platform}-{id}.png` in `DRAWINGS_PATH`, written to a
temporary file and renamed, so it is never half written. Answers `{"platform":"3ds","id":"…","bytes":1234}`: 201 for a new
drawing, 200 when the same bytes are stored already, and 200 when it **replaces** a different drawing of the rating (the
console's latest one wins; a retry after a lost answer is harmless either way).

### Errors

JSON `{"error":"description"}`: 400 for invalid input (fields, content type, size, PNG signature, id), 401 with
`WWW-Authenticate: Bearer` for absent, invalid or expired tokens, 403 for a token of another client, 404 for unknown routes and
ratings, and 429 for the per-client quota (120 requests per fixed server minute, POST and PUT together, including invalid
ones) with `Retry-After` seconds. A network failure or 5xx can be retried with the same id.

## Console configuration

The consoles send ratings to the URL in their private `config.ini`:

```ini
[ratings]
url = https://ratings.hackertours.by.vincent.mahn.ke
```

Authentication reuses the high scores' credentials (`[highscores]` client id and secret of the console; the GBA's link
server uses its `HT_CLIENT_SECRET`): obtain a token with the client-credentials grant from
`https://sso.by.vincent.mahn.ke/realms/sso.by.vincent.mahn.ke/protocol/openid-connect/token`, cache it until shortly
before `expires_in`, and send it as `Authorization: Bearer …`. JWT verification uses the realm's remote JWKS, RS256, the exact
issuer, expiration, and the required `iat`, `sub`, `azp` claims. The backend needs no client secret.

**Trust boundary:** shared console credentials are extractable; this gives platform attribution, not guest identity or
protection against forged ratings.

## Configuration and persistence

| Environment | Default / purpose |
| --- | --- |
| PORT | 3000 inside the container |
| DATABASE_PATH | `/data/ratings.sqlite` |
| DRAWINGS_PATH | `/data/drawings` (created at start) |
| OAUTH_URL | `https://sso.by.vincent.mahn.ke/realms/sso.by.vincent.mahn.ke` (exact issuer) |
| OAUTH_CONSOLE_3DS_CLIENT_ID, `..._XBOX_...`, `..._SWITCH_...`, `..._GBA_...` | the clients allowed to submit: at least one, all distinct; a platform without one gets 403 |

Compose publishes host port **3023** and keeps the database and the drawings in the named volume `ratings`. The process runs as
the unprivileged `node` user. The generated backup/restore workflows cover named Compose volumes; for a consistent manual
snapshot stop the app first (the WAL/SHM files belong to the database).

## Development and deployment

```sh
cd app
npm ci
npm test
OAUTH_CONSOLE_3DS_CLIENT_ID=highscores-hackertours-3ds \
DATABASE_PATH=./ratings.sqlite DRAWINGS_PATH=./drawings npm start
# The deploy workflow uses this exact test target:
docker build --target test .
```

Tests use locally generated RSA keys and an injected local JWKS; no Keycloak or network service is contacted. Their files are
project-relative and removed afterwards.

The repository, DNS/proxy setup, deployment and volume backup workflows, `infrastructure/` and `service/` scaffolding are
generated by `mahn-ke/repos`, which also sets the Actions secrets `OAUTH_URL` and `OAUTH_CONSOLE_{3DS,XBOX,SWITCH,GBA}_CLIENT_ID`
(the ids only, never the client secrets). Compose passes only those into the service.

### First push after Terraform creates the repository

Terraform creates remote bootstrap commits, so do not force-push this independent local history over them. Fetch and merge
the generated history, keeping this implementation where the generated starter files conflict, and push it as a branch for a
PR:

```sh
git fetch origin main
git merge --allow-unrelated-histories origin/main
# Keep local app/, docker-compose.yml and infrastructure/subdomain.tf; keep the generated workflows, infrastructure/ and service/ files.
git push -u origin HEAD:feat/ratings-service
```
